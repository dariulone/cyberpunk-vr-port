# Инвентаризация оставшегося C++ в Rust-сборке

## Этап 8: шейдеры на Rust (с B643)

Собственные шейдеры пишутся на Rust (`rust/shaders/passes`, rust-gpu 0.11) и превращаются в DXIL инструментом
`rust/shaders/builder` (`cargo xtask shaders`): rust-gpu — модуль SPIR-V на точку входа; naga 30 читает его (без
переворота y: соглашения D3D12, как их пишет исходник), проверяет и пишет HLSL с регистрами корневой сигнатуры пасса
(таблица в builder); сэмплеры переписываются из кучи сэмплеров naga в обычные регистры (пассы держат статические
сэмплеры); DXC компилирует в DXIL (валидатор подписывает только верный модуль), а привязки, которые объявляет DXIL, сверяются
с таблицей по листингу DXC. DXIL лежит в `rust/crates/cvr-gpu/shaders` с MANIFEST.txt (коммитится; сборке плагина
nightly не нужен), `cargo xtask shaders --check` пересобирает и сравнивает побайтно. Отдельный workspace: кодогенератору
rust-gpu нужен nightly из `rust/shaders/rust-toolchain.toml`, плагин собирается на стабильном.

Проверка пасса (B643–B650) — `CVR_SHADER_AB` (`cvr-gpu/src/shader_ab.rs`): настоящие вызовы игры (1-й, 90-й и 400-й на
пайплайн, глаз и формат) рисовались ещё раз эталоном (HLSL через FXC, как раньше) и заменой (DXIL из Rust) в две одинаково
очищенные цели, через 2 с байты сравнивались; `CVR_SHADER_HLSL` был путём назад. С B651 оба сняты вместе с HLSL в
Rust-коде (ниже).

Итог (B650): все собственные шейдеры порта — 54 DXIL — собираются из Rust и встроены в DLL; поставляемых файлов от HLSL
больше нет (кроме двойников игровых шейдеров, которые делают инструменты из DXBC игры, — модификация игровых шейдеров, не
этап 8). Подтверждение в игре (симулятор): пиксельный A/B — квады в пространстве и блиты цвета (B643, B645); созданием
пайплайнов движком — 4 подмены PS прицела и 4 двойника scope, 6 вариантов VS мировых меток (B650); остальное — стенд WARP
(бит в бит).

B651: путь назад снят. Подтверждение путей, которых симулятор сам не запускает: стенд `cvr_gpu::bench` на видеокарте игры и
её драйвере (`CVR_BENCH_HARDWARE=1`: первый аппаратный адаптер вместо WARP) — все 8 сравнений шейдеров (оптика, прицел,
обводка, мировые метки, источники, генератор кадров, зеркало) бит в бит с HLSL, собранным так же (стенд нашёл, что для
stream output на видеокарте кучу дескрипторов надо привязать до таблицы — WARP это прощал); тесты single-pass, finer VRS и
групп на видеокарте — с B647/B648; в игре — прогон A/B с `xr_osr=1` и `xr_framegen=1` (OSR и генератор кадров работают в
симуляторе, если их включить). В Rust-коде больше нет ни HLSL, ни FXC/DXC: строки HLSL, `D3DCompile`, `shader_ab.rs`,
загрузка файлов прицела и обводки (`shader_blobs.rs` отдаёт встроенный DXIL), `build.rs` cvr-render (DXC для мировых
меток) и передача DXC в Rust-сборку из CMake сняты; `dxil::pick` берёт один DXIL. HLSL остаётся только эталоном: в
C++-сборке (`src/Shaders`, `src/Render/WorldMarkers.hlsl`, его CMake — только без `CVR_RUST_VRIK`) и в тестах стенда
(`framegen_shaders.rs`, `mirror_shaders.rs` — `cfg(test)`).

2026-11-25: B651 откатан (revert 8f4c0c475) — по умолчанию снова шейдеры C++-сборки: HLSL 13 пассов через `D3DCompile` при
первом использовании, DXIL оптики, прицела и обводки из файлов C++-пакета (`xtask dist` кладёт их снова под прежними
именами), мировые метки из DXC `build.rs`; FSR3 и кодек Neural Rendering — HLSL main (`fsr3_shaders.rs`). Причина: в
шлеме с DXIL из Rust игрок видел артефакты, которых не было на 0.2.45 (стенд WARP бит в бит этого не ловил: драйвер
компилирует DXBC и DXIL по-разному). DXIL из Rust — только по `CVR_SHADER_RUST=1`; `CVR_SHADER_HLSL=<имена>` — HLSL только
для перечисленных.

B652: настоящий pipeline state в игре. Свидетель `cvr_gpu::dxil::witness` в перехватах создания пайплайнов пишет первый

`xr_osr=1`, `xr_framegen=1` с `xr_foveated_dlss=1` и `xr_vrs=1`, `xr_sharpmix=0.5` (CAS; `xr_sharpness` — другое),

оружие с прицелом), а с B654 и маркер `cvr_swapchain_convert.txt` (`ab.ps1 -Prep tools/rust_migration/ab/prep_srgb_convert.ps1`:
рантайм проходит мимо sRGB-формата swapchain) — **37 из 54 сделаны, отказов 0**: квады, блиты, HUD и точка (12), прицел — VS, оба PS и маска (4),

Допуск A/B (задан до переключения, B645): стенд WARP — бит в бит, обязательно; в игре на видеокарте — не больше 2 единиц
в байте на не больше 0,02% пикселей (драйвер по-разному компилирует DXBC от FXC и DXIL от DXC: HUD с sin/cos/pow, накопление
размытия). Найдено A/B: цикл, чьё значение читается после выхода, в HLSL от naga терял последнюю итерацию — такие циклы
разворачиваются вручную (с B646 — общее исправление в сборщике, `pin_break_ifs`).

Паритет с FXC (B648): FXC с /O3 сплавляет произведение и сумму в `mad` (lerp, лучи камеры, `uv * size - j`), переносит
константы в конец (`(c + j) + 0.5`, `mad(uv, size, -j) - 0.5`) и пишет `dot` одной инструкцией `dp3`; написанный по тексту
HLSL шейдер на WARP расходился на единицу в цвете. Шейдер на Rust пишется по листингу FXC (`fxc /T cs_5_0 /E <вход> /O3 /Fc`):
`f32::mul_add` → GLSL Fma → HLSL `mad` → DXIL FMad; `passes/src/common.rs::dot3` — `OpDot`. Вероятно, этим же объясняется
допуск HUD и размытия в игре (B645). Поиск расходящегося шейдера (до B651): `CVR_SHADER_HLSL=<имена DXIL через запятую>` — HLSL
только для них. Сборщик: вендорная naga 30.0.2 (`rust/shaders/vendor`, одно исправление — выборка из массива текстур); `Select` по
размноженному скаляру — по скаляру (HLSL 2021 не принимает векторное условие `?:`); записи в изображения, перечисленные в
`ATOMIC_MAX_STORES`, — `InterlockedMax` (rust-gpu не даёт указатель текселя класса Image).

Шейдеры, работающие в пайплайнах движка (B649). naga называет location `LOCn`, выбрасывает неиспользуемые входы и
ставит позицию последней, а движок связывает VS и PS по регистрам: сборщик переписывает вход PS (`SIGNATURES`) и вход
и выход VS (`VERTEX_SIGNATURES`, с перестановкой инициализатора) по сигнатуре движка — сверено `dxc -dumpbin` с
прежним DXIL элемент в элемент. Корневые сигнатуры, которые плагин строит из самого DXIL, вписываются атрибутом
(`ROOT_SIGNATURES`). Эталоны DXC (fast math по умолчанию) — IEEE-строго (`IEEE_STRICT`, `-Gis`): переупорядочивание
fast math зависит от формы IR, и та же арифметика из naga выходила на одно округление в стороне; строго каждая операция
округляется как написана. rust-gpu пишет `f32::max` и векторные max/min как сравнение с выбором — для эталонов DXC
`passes/src/common.rs::fmax/fmin/max3/min3` (GLSL FMax/FMin), `length_of2` (GLSL Length). Стенд `cvr_gpu::bench`:
вычислительный и графический путь, stream output, буферы констант, DXC для вспомогательных VS; один стенд на процесс
(два графических стенда на общем WARP-устройстве падали параллельно).

Найдено стендом в B650. Вторая ошибка naga в циклах: `continuing` пишется в начале следующей итерации, и выражения тела,
которые он использует, вычисляются там заново — после того, как `continuing` уже сдвинул phi-переменные (выходные значения
второго цикла `vision_highlight` читали следующий тап); сборщик переносит записи в phi заголовка в конец `continuing`
(`defer_header_phi_stores`). `spirv-opt` внутри rust-gpu сворачивает FP: деление на константу — в умножение на обратное
(`x / 0.6` → `x * 1.6666666`), `(x / y) * y` — в `x`; для эталонов DXC такие операции — `common::div` / `common::mul`
(`OpDecorate NoContraction`, свёртка их не трогает). Шейдеры движка, где DXC раскрывает встроенную функцию по-своему, —
через сами встроенные: `normalize3`, `length_of3`, `cross3`, `fract` (GLSL Normalize, Length, Cross, Fract).

## Снимок от 2026-11-13

Снимок от 2026-11-13. В Rust-сборке (`CVR_RUST_VRIK=1`) осталось 44 432 строки C++ в 341 файле `.cpp`. Строки считаются без
комментариев и без веток `#else` эталонной сборки.

### Метод

1. **Мёртвый код по линкеру.** DLL Rust-сборки слинкована с `/MAP`. Затем проверено, у каких объектов линкер с `/OPT:REF`
   не сохранил ни одной функции.
   Результат: целиком мёртвых файлов всего 75, около 970 строк. В основном это держатели экспортов и пустые после
   переноса файлы. Почти весь оставшийся C++ из DLL достижим.
2. **Переключатели.** Для каждого файла собраны экспортируемые переключатели (`*Enable`, `*Request`, `*Mode`, `*Run`,
   `*Capture`, `*Observe` и т.п.) и их значения по умолчанию. Затем найдено, кто их выставляет вне самого файла: другой
   C++, Rust, моды (Lua, redscript, ini) или только инструменты из `tools/`.

Классификация эвристическая. Флаг с ненулевым умолчанием или с записью из модов делает файл «живым». Файл без
переключателей нужно разбирать вручную.

### Вывод для плана

- **Горячий путь** нужно переносить в первую очередь. Это хуки устройства и очередей, кадровый цикл и презентация
  OpenXR, захват, стерео-синхронизация, камера, ввод, оверлей. Именно здесь Rust уменьшает падения: в A/B этой сессии
  C++-эталон каждый раз падает при выходе, Rust-сборка — нет.
- **Исследовательские пробы** нужно либо переносить как есть, либо заморозить и исключить из Rust-сборки (как раньше
  исключены `src/Anim/CharacterRig.cpp` и др.), сохранив их экспорты для инструментов. Это решение владельца проекта:
  исключение убирает функциональность, которую сейчас можно включить из `tools/`.
