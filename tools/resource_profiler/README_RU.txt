CyberpunkVRProfiler 1.0.0 — отдельный профайлер для тестеров
Windows 10/11 x64. Не требует установки, Python, .NET или VC++ Redistributable.

КАК ЗАПУСТИТЬ
1. Распакуйте папку CyberpunkVRProfiler рядом с игрой или в любое удобное место.
   Внутри папки должны лежать CyberpunkVRProfiler.exe и BAT-файлы.
2. Запустите RUN_PROFILER.bat. Можно до запуска игры или когда она уже запущена.
3. Запустите игру обычным способом, воспроизведите проблему.
4. Вернитесь в окно профайлера и нажмите Q, Esc или Ctrl+C.
5. Отправьте всю папку ProfilerLogs\<дата-время-идентификатор> в ZIP.
   Точный путь профайлер показывает в своём окне. Время в именах и логах — UTC.

RUN_5_MINUTES.bat автоматически завершит сбор через 5 минут.
RUN_FULL_THREADS.bat пишет каждый поток на каждом замере, включая спящие.
Без BAT можно просто запустить EXE. Папка логов создаётся рядом с EXE.
При отсутствии прав записи используется %LOCALAPPDATA%\CyberpunkVRProfiler\ProfilerLogs.
Обычный запуск не требует администратора. Недоступные метрики отмечаются явно.
Игра запускается отдельно; после её выхода профайлер продолжает запись.

ЧТО СОБИРАЕТСЯ
- Все процессы: имя, PID и время создания, CPU, рабочая RAM, private commit,
  число потоков/дескрипторов, скорость I/O, dedicated VRAM и shared GPU memory.
- CPU каждого потока: PID/TID, имя потока (если доступно), user/kernel CPU,
  переключения контекста, приоритет, числовые состояние и причина ожидания.
- GPU каждого процесса, по адаптерам и движкам (3D, Copy, Compute, Encode и т.д.).
- Общая GPU-память по адаптерам, системная RAM/commit, длительность замера.
- Появление/исчезновение процессов и ошибки счётчиков.

ФАЙЛЫ
summary.txt         Читаемая сводка всех программ и 100 самых занятых потоков.
summary.csv         Пики и средний CPU по процессам, число валидных замеров.
thread_summary.csv  CPU и переключения контекста всех наблюдавшихся потоков.
processes.csv       Все процессы на каждом замере (по умолчанию раз в секунду).
threads.csv         CPU потоков во времени.
gpu_engines.csv     GPU каждого процесса по движкам и адаптерам.
gpu_memory.csv      GPU-память каждого процесса отдельно по адаптерам.
adapters.csv        Суммарная память и busiest-engine GPU по адаптерам.
system.csv          RAM/commit системы и время работы сборщика sample_work_ms.
session.log         Конфигурация, видеокарты/драйверы, события, ошибки и активные программы.

CSV: UTF-8, разделитель запятая, десятичный знак точка. В Excel используйте
импорт CSV с UTF-8. Размеры — MiB (1024*1024 байт), время UTC.
Файлы сбрасываются после каждого замера. Сводки обновляются раз в 30 секунд
и при штатном завершении. После аварийного завершения отправляйте и частичные логи.

КАК ПОНИМАТЬ ЦИФРЫ
CPU процесса cpu_machine_pct: 100% означает загрузку всей машины.
CPU потока cpu_one_core_pct: 100% означает загрузку одного логического ядра.
cpu_one_core_pct процесса может превышать 100%, если работают несколько потоков.
CPU считается по времени выполнения, а не по частоте/utility из Диспетчера задач.
Первое наблюдение CPU пустое: для процента нужны два замера.
Из-за дискретности учёта CPU на коротких интервалах возможны небольшие скачки
выше 100% одного ядра; исходные измерения сохраняются без обрезания.

По умолчанию --threads active охватывает ВСЕ процессы. В threads.csv записывается
первое наблюдение каждого потока и последующие замеры с CPU или переключениями
контекста. Неизменившиеся спящие потоки пропускаются. Для полной сетки по времени
используйте RUN_FULL_THREADS.bat / --threads all. Идентичность включает время
создания: повторно использованные PID/TID не смешиваются.

GPU — загрузка самого занятого движка, а не сумма всех движков.
GPU/VRAM получаются из счётчиков Windows WDDM и зависят от поддержки драйвера.
GPU по CPU-потокам недоступен: здесь нет ложной привязки GPU к TID. Также нет
FPS, времени отдельных кадров, стеков вызовов или GPU shader-thread profiling.
Для таких данных нужна отдельная трассировка/инструментация.

Dedicated VRAM и shared GPU memory записываются отдельно. Shared — системная RAM,
доступная GPU. На встроенной GPU dedicated память не обязательно физическая VRAM.
Переполнение VRAM/выгрузку ресурсов нельзя доказать одним этим счётчиком.
Память, общая для нескольких процессов, может учитываться в каждом из них:
НЕ складывайте VRAM процессов для оценки общей занятости; смотрите adapters.csv.

Пусто/N/A означает отсутствие достоверного замера, а не ноль:
  ok                 — получено валидное значение (включая настоящий ноль);
  no_instance        — у процесса нет экземпляра этого GPU-счётчика;
  unavailable        — счётчик недоступен/ещё прогревается;
  invalid_or_partial — часть данных невалидна, итог не вычисляется.
Первый GPU-замер обычно прогревочный. При ошибках смотрите session.log.
Опрос может пропустить процессы/потоки, которые успели появиться и завершиться
между замерами; CPU короткоживущих потоков попадёт в CPU процесса, но не всегда
в детализацию по потокам. Имена потоков могут быть пустыми из-за прав доступа.

НАСТРОЙКИ (из командной строки)
CyberpunkVRProfiler.exe --duration 300
CyberpunkVRProfiler.exe --interval-ms 500 --threads all
CyberpunkVRProfiler.exe --threads target --target Cyberpunk2077.exe
CyberpunkVRProfiler.exe --output "D:\Test logs" --duration 60
CyberpunkVRProfiler.exe --help

--threads target ограничивает только детализацию CPU потоков; GPU/VRAM/CPU
процессов всегда собираются для всех программ. --threads none отключает потоки.
Интервал 250..60000 мс; меньший интервал увеличивает объём и нагрузку сборщика.
Длительность 1..86400 секунд; без --duration сбор идёт до ручной остановки.

Логи содержат имена запущенных программ/потоков и параметры оборудования.
Нет сети, загрузки логов, внедрения DLL, установки драйверов или изменения игры.
Для удаления достаточно удалить папку профайлера и его логи.
