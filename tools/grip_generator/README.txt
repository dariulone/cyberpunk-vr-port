Cooked-mesh input for grip generation

This C++ tool reads extracted CR2W meshes and decodes their highest-detail
render geometry through the installed game's Oodle library. It keeps one mesh
in memory. No floating-point geometry is generated by an orchestration script.

Build:
  cmake -S tools/grip_generator -B build/grip_generator -A x64
  cmake --build build/grip_generator --config Release
  ctest --test-dir build/grip_generator -C Release --output-on-failure

The build reuses the repository's downloaded nlohmann/json headers. Set
CVR_JSON_INCLUDE to a directory containing nlohmann/json.hpp if needed.

Single mesh:
  grip_generator OODLE_DLL FILE.mesh REPORT.json [GEOMETRY.obj]

Independent validation against a WolvenKit MeshOnly, highest-LOD GLB export:
  grip_generator --verify OODLE_DLL FILE.mesh REFERENCE.glb
All vertex positions and triangle topology are checked, including the exporter's
coordinate conversion. Opposite triangle winding is reported explicitly.

Batch:
  grip_generator --batch OODLE_DLL MANIFEST.jsonl CATALOG.jsonl
Each manifest line contains source (absolute extracted file path), path (depot
path), hash (hexadecimal depot hash), and archive (source archive path).
Keep different archive versions separate. The tool does not guess which archive
wins at runtime. Repeated entries for the same archive/hash can be deduplicated
only after verifying that their content hashes agree.

Every manifest entry produces a catalog record. Unsupported layouts, absent
render geometry and invalid indices are reported instead of invented geometry.
The process exits nonzero if any record fails. Windows paths longer than
MAX_PATH are supported. The output can be read while a batch is running with
FileShare.ReadWrite.

Emit a runtime-format radial-profile table, sorted by depot hash:
  grip_generator --emit-profiles CATALOG.jsonl PROFILES.inc
Identical archive variants are deduplicated. Hashes with different radial
profiles across archive versions are excluded and counted, rather than choosing
an unverified load order. Inspect the generated table before runtime integration.

For small meshes with an elongated, approximately square cross section, the
catalog also includes a conservative radial envelope in sixteen axial slices.
Triangle edges are clipped at slice boundaries, so sparse vertex rings do not
lose long sides. Disconnected axial gaps are rejected. This envelope is suitable
input for the existing round-prop grasp path, but is not an exact reconstruction
of arbitrary meshes. Large environment meshes remain in the geometry catalog.

Fit a radial-profile grasp using the production solver and real FPP hand skin:
  grip_pose_baker RIG PROFILE_JSON OUTPUT_PREFIX SAMPLE_Z_M REVERSE_AXIS
REVERSE_AXIS is 0 or 1. The input is one catalog row containing round_profile;
include its depot hash to emit accepted runtime seat records. The fitter writes
both hands' nineteen local rotations and reference-relative deltas to JSON,
PPM previews, and an include containing accepted seat adjustments. It checks
visible skin penetration and precision-pad contact on the selected stem, plus
functional joint limits. Calculations, mirroring and optimization run in C++.

After integrating the emitted seat records, append --verify-runtime to the same
command to compare the runtime seat and all nineteen rotations with that JSON.
The solver still adapts the fingers to the current rig at runtime. The supplied
offline hand-mesh fixtures cover female FPP hands; other body variants and live
contact need separate validation. Arbitrary non-round meshes are not yet fitted.

Find existing world instances for live tests without spawning a different entity:
  grip_sector_refs OODLE_DLL ARCHIVE_FOLDER SECTOR_NAMES TARGET_DEPOT_PATH OUTPUT_JSONL
SECTOR_NAMES contains one depot path per line. The tool scans the first archive
segment of those streaming sectors for the literal path and its depot hash.
Matches are candidates to inspect, not validated placement records. Resolve
node-data indices through the sector's root node handle array before using them.

Bake grasps for every hand-sized prop mesh (the runtime table):
  grip_pose_batch RIG OODLE_DLL CANDIDATES.jsonl OUT.jsonl SHARD SHARDS [PREVIEW_DIR PREVIEW_EVERY]
  grip_pose_batch --pack mods/config/CyberpunkVR_MeshGrasps.bin OUT_0.jsonl OUT_1.jsonl ...
A candidate row is a geometry catalog row (hash, path, minimum, maximum, round_profile or null) plus the
extracted cooked file as "source". Run SHARD 0..SHARDS-1 as separate processes. For each mesh the tool builds
a signed distance field of the drawn triangles (exact in a band, chamfer distance beyond it, so far fingers still
see the surface), takes the primitives the game seats it by (its bounding box; for a round mesh the whole
cylinder and every GraspPartOf part: neck, stem, body), runs the production Seat (with the mesh's seat fit) for
each way the primitive can lie on the palm, closes the production finger solver on the drawn surface, shifts and
tilts the seat for the best fit against the FPP hand skin, and swings the drawn thumb onto the surface. Accepted
grasps keep no skin in the mesh, the pads that should touch do, and the joints stay in their functional ranges.
GRIP_PREVIEW_SIZE sets the preview size (PPM, three views; red thumb, green little finger).
The packed table (version 2) is read by src/Anim/GraspPose.cpp GraspLoadBaked from the plugin's grips folder;
src/Natives/HeldBody.cpp replaces the game's seat by the nearest baked grasp (25 degrees, 3.5 cm) and puts on its
baked fingers. A mesh, or a seat, the table does not cover keeps the solved grasp.
The candidate list: tools/grip_generator/batch_candidates.py (hand-sized decoration/item/prop meshes from
build/grip_meshes_20261116/geometry_catalog_v2.jsonl), then batch_sources.py (each row's extracted cooked file).
