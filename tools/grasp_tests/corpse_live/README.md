# Attach-only corpse regression

The game is started and stopped separately by the root agent. `run.py` never starts, terminates, restarts, or requests a manual save of Cyberpunk. It kills only its explicitly spawned temporary NPC. A bridge timeout or failed test leaves the game running and records the failure. Acquire an exclusive runtime/bridge lease before using it; never run beside RenderDoc replay.

Before any settings, input, equipment or world mutation, the harness queues a unique `CPVR_CorpseAudit_<uuid>` ADD request to the native SaveLocksManager. When exposed, it verifies its own membership plus both manager/engine saving checks. The actual host does not expose `m_saveLocks` and does not acknowledge dispatch through ObserveAfter. There it accepts only the root's independently verified `GoalSaveGuard` token (causal remove/re-add or observed dispatch), together with current manager/engine locked checks. A generic locked bit alone is insufficient. Standalone use without observable membership or verified root refuses all gameplay mutations. Pending autosaves are invalidated before starting. This uses the game's save-lock system, not combat/no-save gameplay hacks.

## Build and run

```powershell
cmake -S tools/grasp_tests/corpse_live -B build/corpse-live
cmake --build build/corpse-live --config Release
ctest --test-dir build/corpse-live -C Release --output-on-failure
py -3.13 tools/grasp_tests/corpse_live/run.py --pid GAME_PID --out scratch/corpse-live-shin --case shin
```

Omit `--case` for shin, forearm, same-part two-hand, and different-limb two-hand cases. Repeat `--case` to select several. The output directory must not already exist. `--trace` temporarily enables the existing physics trace setting and restores its original bytes. No dependencies are installed: CMake uses the project's existing nlohmann JSON headers (`JSON_INCLUDE` can override their location).

The deployed DLL must provide `VRPhysHeldBody(side)`. Its `array:Uint64` contains `[active, stable proxy ID, body index, ageMs, exactContactErrorMicrometres]` from the completed physics hold snapshot. These are integer engine IDs, not pointers. Field 5 is the distance from the actual body-local grip to its prepared drive target, both in world space; `UINT64_MAX` means unavailable. Lua's submitted `graspState.fast` alone does not prove the native simulation accepted or retained a grip. Both are checked here. Old four-field DLLs can be sampled, but cannot pass exact-contact coverage.

It must also provide `VRBodySolverMass(proxy,body)`. Before the first grip, the harness reads physical mass for all available bodies of that ragdoll. During holds and after release it records the uncached mass separately from normalized `VRBodyInfo.w` (`reportedCarryMass`). For the current fixture the required observations are physical5→100 while held, remaining100 with one of two holders still attached, and physical100→5 after the last release. A cached carry-mass5 cannot prove restoration. `mass-events.json` and `mass-baseline-*.json` retain that evidence; loss of an actor is accepted only if its earlier physical release was actually verified.

## Numerical ownership and calibration

All pose generation, quaternion work, geometry, calibration solves, trajectory interpolation and numerical analysis run in compiled `corpse_probe.exe`. Python performs file I/O, process-memory writes through the existing simulator harness, IPC, scheduling, sampling and capture. It does not use `Sim.glide`, Python quaternion helpers, or Python-generated trajectories. Lua only reads game state and invokes native operations.

The C++ planner reads the actual dead NPC's attachment slots. Before choosing the footprint it measures model-space shoulders, current FK arm lengths and actual camera height above the player feet from LogVRDiag. Forty-eight candidates combine six facing directions, four front offsets and two lateral offsets; each has five static ground rays. Same-floor candidates are ranked by predicted shoulder-to-palm distance and reach excess. The measured FK length is a ranking input, not a replacement production reach cap. `--spawn-distance` can place the temporary NPC on an open side of the initial location; `--grip-head-height` specifies tracking-space posture, whose actual world eye/shoulder height is recorded separately. The player turns using measured forward-vector feedback; turn rate is updated from each observed response instead of assuming a fixed user setting.

For each hand, four orientation probes and four position probes estimate local three-axis Jacobians. Each perturbation is bracketed by a settled repeat of the baseline. The orientation solve transforms the drawn palm basis back through the drawn wrist and then through the raw wrist. Position solving uses raw wrist plus rotated palm skin. Contact-constrained drawn motion is therefore not mistaken for a static controller mapping. Exact drawn-palm convergence is not required before grip: a bounded approach uses actual `canGrabNear`, then the completed native hold/selected anatomy is the acceptance gate. A singular or non-converging raw mapping still stops the test.

The numerical self-test verifies a rotated/translated calibration frame, quaternion orientation response, preservation of hand separation during paired rotation, unchanged controller orientations in that test, and rejection of missing evidence. This does not prove live acquisition will succeed in every environment.

`corpse_probe pair-geometry input.json` performs offline analysis of the paired samples. It compares raw/drawn wrist and desired-grip spans with the rigid grip span, reports the minimum possible mean contact error from incompatible lengths, and independently reconstructs the exact left contact when its reference/native bodies match. The other local point is explicitly an approximation inferred from preceding one-hand samples, with its measured spread retained. PID26944 showed that rotating a fixed controller-wrist baseline does not by itself make two actual body contacts geometrically compatible: target466mm versus rigid≈147mm produced the observed large two-hand residual. That case proves retention/mass ownership, not ideal visual seating.

## Cases and proof gates

- One-hand shin and forearm: acquire the requested anatomical segment of an actual dead ragdoll; rest; lift; sideways motion; wrist rotation; stand; walk; stick turn; move the controller beyond reach and hold for 4.5 s; drop and regrab.
- Outside-reach success requires measured raw-to-drawn wrist separation over 45 cm for at least 3 s, with a continuing native hold. Sending a far-away controller command alone cannot pass this gate.
- `--reach-mode lateral` retains the original lateral stress; `--reach-mode floor` is an explicitly synthetic contact stress that moves raw tracking below the virtual floor, with the same measured separation/duration requirement. It does not replace natural walking/standing. The initial lateral live run retained the grip but failed coverage because measured separation was only119mm; this was not reported as a passing reach regression.
- Walking requires both actual player displacement and actual corpse-hip displacement. Holding a stretched limb while the torso remains behind cannot pass.
- Same-part two-hand: acquire the torso or explicit `--pair-part shin` fixture with one hand, lift, then query the actual held actor's surface for a bounded set of second contact offsets. Both completed native hold IDs must match. Generated paired motion rotates the line between hands while leaving controller rotations fixed. The actual held body must rotate at least 10 degrees.
- Different-limb: acquire right and left forearms. Actual proxy IDs must match and body indices must differ. Lift and walk while both native holds remain valid; release one hand and prove the other continues holding.
- Drop requires both Lua and native holds to be off. Regrab requires a new successful acquisition.

Samples include actual drawn/raw hand frames, Lua grasp data and whole mass, original reference-body poses, resolved native-body poses/mass, native hold IDs/age/exact contact error, NPC death state, player position and corpse hips. `acquisitions.json` preserves planned and actual anatomical segments. One-hand shin/forearm accepts either shin12/13 or forearm8/9; paired different-limb acquisition remains side-specific. `report.json` lists every phase's evidence, continuity failures, duration, travel, rotation, reach duration, per-hand exact contact coverage and the separately labelled reference-grip distance. Each required hand needs at least three valid exact-contact samples and 90% coverage; invalid/sentinel samples are never interpreted as zero error. The existing 20cm p95 test limit applies to exact contact error. Missing, stale, wrong-kind, wrong-part, insufficient-motion and wrong two-hand-relationship evidence is a failure. Reference-grip distance is diagnostic only: a natively reselected nearby body can introduce reference-joint articulation, so it cannot establish direct PhysX contact slip. Failure captures include full state, LogVRDiag shoulder/length data and L/R images before cleanup.

L/R/SBS stills and short HEVC MP4 clips use `simxr.shot`/`record_start`, not the simulator mirror bitmap. Visual inspection remains required for finger seating, cloth penetration and motion quality; a numerical PASS alone is not a claim that all corpse behavior is perfect.

## Restoration

Before mutation the harness captures player position/orientation, active/equipped weapons, ArmsCW, currency, holster preference, full controller/body-state bytes, simulator head pose and relevant setting-file bytes. It uses a non-persistent tagged NPC, hides holsters to prevent belt grabs during calibration, and temporarily holsters the active weapon.

In `finally` it releases grips/sticks, stops only its recording, checks uncached physical mass before deleting the tagged NPC, restores player position/facing, active weapon, controller/body state, head and setting files, then verifies no remaining hold/NPC, equipment/currency equality, the entire inventory's exact combined-ID/quantity map and position/orientation tolerances. Head restoration uses the simulator's runtime status precision (three decimal places); controller state is restored byte-for-byte. Only after successful restoration does it invalidate pending autosaves and queue REMOVE for its own unique lock. Removal is verified when the reason list is observable; otherwise the report explicitly leaves own removal unconfirmed and verifies continued protection by root's retained token. It never removes root's or another mod's lock. Cleanup failures retain the lock and `CorpseAudit` for root repair. Unknown extra inventory is reported for exact-ID review, never automatically deleted. No game-stop function exists in the harness.

The full inventory gate was added after PID26944's final independent audit found one extra `Gen_Misc/Prop` item even though equipment/currency matched. Its unique ID was proven absent from the root's baseline, removed under the retained root lock, and the complete map was verified equal. `inventory_test.py` covers that extra Prop, missing/replaced unique IDs and quantity changes. Earlier `restored.json` files lack this gate; their inventory restoration must be assessed using the separate final audit, not their original PASS alone.

`original.json`, `simulator-original.json`, `settings/`, `save-lock.json`, `save-lock-release.json`, generated math inputs/results, raw `samples.json`, `phases.json`, mass evidence, `restored.json`, `cleanup.json` and media are retained for review. Outputs are evidence, not permission to declare completion without inspecting them.

Earlier exploratory sessions lacked this autosave lock. They did not request manual saves, but the game still wrote autosaves during temporary changes. Root backed up the saves, reversibly archived the identified test autosaves and pinned the next launch to untouched AutoSave-13. In-memory restoration alone must never again be described as proof that save files were untouched. PID20040 verified the retained root guard and physical mass5→100→5 during a real one-hand hold; the new exact-contact and paired-holder proof still requires the next approved session.
